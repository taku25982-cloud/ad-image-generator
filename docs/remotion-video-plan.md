# 広告動画生成機能（Remotion） 要件定義・実装計画

## 1. プロジェクト概要
静止画の広告画像生成プラットフォームに、新たに **Reactベースの動画生成フレームワーク「Remotion」** を組み込み、動的な広告動画（MP4等）を生成・プレビュー・出力する機能を追加する。
最終的なホスティングは Netlify（無料プラン）を想定しつつ、動的なモーショングラフィックス動画をブラウザでプレビューし、MP4としてダウンロードできる体験を提供する。

## 2. 確定した要件（仕様）

### 2.1. 表現・構成・尺（Duration）
- **スタイル**: 画像のスライドショーに留まらず、テキスト（キャッチコピー）がアニメーションで浮かび上がったり、図形（シェイプ）がダイナミックに動く **モーショングラフィックス主体** の表現。背景や素材としてAI生成画像を活用する。
- **尺（長さ）の選択肢**: 短尺広告として最適な以下の3パターンをシステム側で用意し、ユーザーが選択可能とする。
  1. **6秒（バンパー広告）**: 最短で強烈なインパクトを残すスキップ不可広告サイズ。
  2. **15秒（標準ショート）**: TikTok/Reels/Shorts の基本となる長すぎず情報量を伝えられるサイズ。
  3. **30秒（ストーリー型）**: より詳細な説明や、物語構成（課題提起→解決→オファー）を入れる長めのサイズ。

### 2.2. フォーマット（アスペクト比）
各種SNSプラットフォームに合わせて最適化された動画を生成できるよう複数対応する。
- **縦型 (9:16 / 1080x1920)**: TikTok, Instagram Reels, YouTube Shorts 向け（最優先）
- **正方形 (1:1 / 1080x1080)**: Instagram Feed, Facebook 向け
- **横型 (16:9 / 1920x1080)**: YouTube 本編広告, X (Twitter) 向け

### 2.3. 音声（オーディオ）オプション
動画の魅力を高めるため、以下の2つの音声要素をそれぞれ **「ON/OFF 選択可能」** とする。
- **BGM**: プリセットのフリーBGMをいくつか用意し、雰囲気に合わせて付与できる。
- **AI Voiceover (独自のAI音声ナレーション)**: 入力されたテキストやシナリオをもとに、AI音声（ElevenLabs等）でナレーションを生成して合成できる。

### 2.4. ユーザー体験（UX）フロー
現状の仕様に基づき、シンプルなワンストップ体験を提供する。
1. **要件・素材入力**: 商材のテキストやターゲット層を入力し、**画像生成時と同様に既存の画像ファイルを素材としてもアップロード・指定できるようにする**。オプション（尺、比率、音声有無）を選択。
2. **AI処理**: LLM が「動画シナリオ（カット割り）」「字幕テキスト」「背景画像プロンプト」「ナレーション原稿」を JSON 形式で自動生成。
3. **ブラウザプレビュー**: 生成データを Remotion の `<Player />` に渡し、ブラウザ上で即座に動画のアニメーションを再生・確認。
4. **MP4出力・ダウンロード**: プレビューした内容を .mp4 ファイルとしてサーバーでレンダリングし、ダウンロード。

## 3. 🚨 技術的課題とアーキテクチャ設計（最重要コンポーネント）

### 【課題】Netlify無料プランにおけるレンダリングの壁
ユーザーの希望する「最終的に無料プランのNetlifyにデプロイする」という要件に対し、Remotion における **MP4動画のレンダリング機構** には以下の致命的なインフラ制約が存在します。
- RemotionのMP4生成には Node.js, **Chromium（ヘッドレスブラウザ）**, FFmpeg のバイナリが必要です。
- Netlify Functions（サーバーレス関数）は無料枠では「パッケージサイズ上限（約50MB）」の制約があり、数百MB規模の巨大なバイナリを含めることは実質的に不可能です。

### 検討: FFmpeg.wasm と Netlify Background Functions の活用について
別の動画アプリ等で行われている「FFmpeg.wasm によるブラウザ完結処理」や「Netlify Background Functions（15分実行可能）」は非常に優れたアプローチですが、**Remotionに限ってはそのまま適用できない特有の事情**があります。
- **なぜFFmpeg.wasmだけではダメなのか**: 既存の動画ファイル(.mp4など)をカットしたり変換するだけであればFFmpeg.wasmでブラウザ上で完結します。しかし、Remotionは「Reactで描画された画面アニメーションを、裏側で立ち上げたChromiumが1コマずつスクリーンショット撮影し、それをFFmpegでパラパラ漫画のようにつなぎ合わせてMP4を作る」という仕組みです。つまり「ブラウザ（Chromium）本体をサーバー内で起動する」プロセスが必要不可欠なため、クライアントサイドのFFmpeg.wasmだけではReactコンポーネントをMP4にエンコードできません。
- **なぜBackground Functionsを使わないのか**: 実行時間（10秒の壁）はクリアできますが、ChromiumとFFmpegを展開するための「パッケージサイズ（50MB制限の壁）」に抵触してデプロイできないというインフラ上の物理的な壁が存在します。

### 【解決策アーキテクチャ】フロントエンドとレンダラーの分離
上記のRemotionの仕組み（Chromium必須）を鑑みて、Netlify（フロントエンド）と、動画をレンダリングするバックエンド（計算資源）を分離するアプローチをとります。

1. **ホスティング（Netlify）**: サイト自体、素材のアップロード、AIのやり取り、Remotion `<Player />` によるプレビュー機能までは Netlify 上のフロントエンドとしてすべて完結して動かします。
2. **レンダリングサーバーの分離**: `npm run build` でRemotionのプロジェクトをバンドルし、これを Render.com や Railway などのコンテナ枠（実行時間やサイズの制約が緩くヘッドレスブラウザが動かせる環境）、あるいは専用の AWS Lambda (`@remotion/lambda`) にアップロードし、「動画をレンダリングして完成URLを返す専用API」として立ち上げます。

**結論**: ユーザーが「ダウンロード」を押した瞬間に、Netlify からこの外部レンダリングAPIへ構成データ（JSONや画像URL）を投げ、完成したMP4をダウンロードさせる設計にします。

## 4. 開発ロードマップ（ステップ）

- [ ] **Step 1: Remotion 基盤の導入**
  - アプリ内に Remotion 用のパッケージとディレクトリを構成。
  - テスト用の Hello World 動画とブラウザ埋め込み用 `<Player />` の表示確認。
- [ ] **Step 2: 選べる3つの動画フォーマットと尺の設計**
  - 入力されたテキストや「素材画像」をもとに構成できるベース・コンポーネント（Composition）を作成。
  - 尺（6s, 15s, 30s）とアスペクト比（9:16, 1:1, 16:9）を動的に切り替える変数の定義。
- [ ] **Step 3: モーショングラフィックス・アニメーションの実装**
  - タイトルが浮かび上がるタイポグラフィアニメーションの実装。
  - ベースに敷いた画像のKen Burns（ゆっくりズーム・パン）エフェクトの構築。
- [ ] **Step 4: 音声オプション（BGM / AIナレーション）の統合**
  - Remotionの `<Audio />` コンポーネントを用い、BGMのON/OFF連動、ElevenLabs等を使った音声合成を追加。
- [ ] **Step 5: レンダリングAPIとの疎通**
  - 外部レンダリングサーバー用のシンプルなレンダリングスクリプトの構築。
  - フロント（Netlify）から引数（JSON）を渡してMP4 URLを取得・ダウンロードするロジックの完成。
